# Grok 服务器 API-only 拆除计划

## 1. 目标

将生产服务器上的 Grok 部署从“API + 自动注册流水线”收敛为“仅 API 服务”，保留现有账号池、API Key、OpenAI/Anthropic 兼容接口及必要的账号维护能力，移除自动注册、待处理恢复、浏览器审批器、注册队列工作器及其专用资源。

## 2. 控制目标与验收指标

把部署视为一个闭环：当前服务器状态是被控对象，部署操作是执行器，容器状态、健康检查与真实 API 请求是测量反馈；只有反馈满足下列指标才结束。

| 指标 | 目标 |
| --- | --- |
| API 可用性 | `/v1/models`、OpenAI 聊天接口、Anthropic 消息接口保持可用 |
| 数据完整性 | 现有 `data/`、账号池、API Key 不删除、不重建 |
| 注册能力 | 自动注册生产者、恢复任务、mint worker、浏览器审批器不再运行，也不会被重启策略拉起 |
| 资源收敛 | 注册专用容器、镜像构建依赖和运行时配置从生产编排中移除 |
| 中断时间 | 优先零中断；如 API 必须重启，实际中断控制在 60 秒内 |
| 稳定性 | 部署后连续观测容器健康、错误日志和真实 API 请求，无持续 5xx/重启循环 |
| 可回滚性 | 修改前保留服务器编排文件、当前镜像标识和数据备份/快照信息，可恢复到原拓扑 |

## 3. 已知现状

- 本地仓库根服务为 FastAPI API 网关，同时混入注册控制器与管理台入口。
- `docker-compose.server.yml` 当前包含 API、两个 Mihomo、两个 RuyiPage 审批器、注册生产者、pending recovery 和可选 mint worker。
- GitHub 基线 `HM2899/grokcli-2api` 的主线仍是 API 网关项目；GitHub 同类项目普遍把“API 网关”和“注册/Turnstile/浏览器”作为可拆分部署单元。可借鉴的核心经验是：账号凭据作为持久数据输入，注册流水线不应成为 API 请求路径的硬依赖。
- 当前工作分支为 `codex/grok-registration-recovery`；正式交付前需合并至 GitHub `main`。

## 4. 边界与假设

### 保留

- Grok OpenAI 兼容 API。
- Grok Anthropic 兼容 API。
- 现有账号池、Token 自动续期、模型健康检查及 API Key 校验。
- API 请求实际需要的网络出口；是否保留一个 Mihomo 由服务器实测决定。
- 管理台中与账号查看、导入、启停、API Key 管理有关的能力（如果它们与运行 API 共用进程）。

### 移除

- `registration-producer`。
- `pending-recovery`。
- `registration-mint-worker*`。
- `ruyipage-approver*`。
- 注册专用队列、指标和 cookie/pending 处理的运行时挂载与环境变量。
- 注册专用代理实例；若 API 本身不需要代理，则两个 Mihomo 都移除，否则只保留 API 必需的最小实例。
- 管理台/API 中触发新账号自动注册的入口；优先通过现有功能开关禁用，若无开关再做最小代码改动。

### 不做

- 不删除服务器 `data/` 中现有账号或 API Key。
- 不重写 API 核心代理逻辑。
- 不顺带清理与本任务无关的历史代码或数据。

## 6. 回滚策略

1. 若仅停止注册容器后 API 异常，立即按原 Compose 启回 API 所需的网络 sidecar，不恢复注册生产任务。
2. 若 API-only 配置导致核心请求失败，恢复备份的 Compose/环境配置并以原镜像重建 API。
3. 全程不回滚或覆盖 `data/`；数据层只做备份与只读核验。
4. 回滚后重复健康检查、模型列表与真实 API 请求，确认系统回到稳定状态。

## 7. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| API 误依赖注册代理/审批器 | 服务器先做网络与依赖实测，再决定是否保留一个最小代理 |
| Compose 删除服务但旧容器仍运行 | 上线时显式停止、删除并使用 `--remove-orphans` |
| 注册端点仍可触发后台任务 | 配置或代码层明确禁用，并用 HTTP 验证 |
| 账号池被误删 | 不操作 `data/`，上线前记录备份/快照与文件数量 |
| API 重建造成长中断 | 先拉取/构建，最后一步才替换容器；健康检查通过后切换 |
| 当前分支与 `main` 有偏差 | 合并前检查提交图和远端差异，不覆盖他人变更 |
